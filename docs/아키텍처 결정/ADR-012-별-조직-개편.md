# ADR-012 15팀 41명 조직 개편과 Codex 구현 허용

2026-11-08 Zero가 회사를 처음부터 다시 설계했다. 회사가 하는 일, 팀, 인원, 엔진 배정, 이름 체계를 정했다. 이 ADR은 조직과 권한만 다룬다. 일이 흐르는 운영 규칙(기획 보고, 대표 결정, 결과 보고)은 따로 정한다.

운영 규약 1.2의 그리스 문자 이름 규칙과 1.3의 "Codex는 읽기 전용 일에만"을 대체한다.

## 회사가 하는 일

- 밖으로 파는 것: 앱·웹 제품(가게씨, 오롯, Jday)과 회사·직원 이야기를 담은 유튜브 콘텐츠
- 안에서 Zero를 돕는 것: 교육(회사 운영에 필요한 지식 학습)과 비서(회사 전체 점검과 Zero에 대한 분명한 피드백)

## 조직

15팀 41명이다. 팀장은 모두 Claude, 팀원은 일에 따라 Claude 또는 Codex다. 전체 Claude 21명, Codex 20명이다.

괄호에 Claude라고 적지 않은 팀원은 Codex다.

- 엔진 원칙: 판단, 보고, 사용자와 시청자에게 보이는 결과는 Claude가 맡고, 코드, 테스트, 집계, 조사, 평가, 제작은 Codex가 맡는다. Codex 팀원이 만든 결과는 Claude 팀장이 최종 검토한다
- 41명을 모두 등록하지만, 시장·콘텐츠 팀과 재무는 출시와 유튜브 시작에 맞춰 일을 맡기 시작한다. 그 전에는 일이 배정되지 않는다
- 비서는 제갈량이나 방통 같은 참모다. 현실을 직관적으로 짚어 분명하게 말하고, 최종 결정은 Zero가 한다

## 이름

직원 이름은 별 이름이다. 별의 실제 특징이 역할과 맞도록 골랐다(예: 북극성 폴라리스가 비서, 시력 검사에 쓰던 미자르가 QA팀장). 그리스 문자는 24개뿐이라 41명을 채울 수 없었다.

기존 12명은 새 이름으로 옮겼다. 예전 이름은 `org.yaml`의 `former`에 남겨, DB와 Discord에 남은 예전 기록도 새 이름으로 보이게 한다.

| 예전 | 새 이름 | 예전 | 새 이름 |
|---|---|---|---|
| Beta | 아르크투루스 | Eta | 투반 |
| Gamma | 알비레오 | Iota | 베텔게우스 |
| Alpha | 리겔 | Theta | 폴라리스 |
| Delta | 미자르 | Kappa | 알데바란 |
| Epsilon | 알니탁 | Lambda | 폴룩스 |
| Zeta | 샤울라 | Mu | 시리우스 |

## Codex 구현 허용

이번 개편으로 개발팀 실무를 Codex가 맡으므로 구현·수정 단계를 연다.

- Codex는 구현(IMPLEMENT)과 수정(FIX) 단계에서만 `workspace-write` 샌드박스로 작업 worktree에 쓴다. git worktree의 커밋은 원래 저장소의 `.git`에 쓰이므로 그 폴더를 `--add-dir`로 함께 연다
- 기획·디자인·설계 문서를 쓰는 단계는 Claude만 맡는다. Claude는 단계마다 쓸 수 있는 폴더를 도구 권한으로 좁힐 수 있지만, Codex 샌드박스는 worktree 전체를 열기 때문이다
- 만든 사람과 검증하는 사람을 다르게 두는 R1은 그대로다. 구현(Codex)은 개발팀장 확인과 QA팀장 리뷰(둘 다 Claude)를 거친다

## 따르는 변경

- 비공개 회사 설정(`~/.zerosync/company`)의 `org.yaml`, 인격 파일 41개, `pipelines/`(예시를 새 이름으로 옮긴 것)
- `bot/projects.yaml`의 제품 담당, 교육·비서 담당, 그림 담당 이름
- 저장소 예시(`examples/company`)와 코드 기본 조직은 그대로 둔다. 회사 설정이 없을 때 쓰는 최소 예시이기 때문이다

## 남은 일

- DB에 예전 이름으로 쌓인 실행 기록은 대시보드의 직원별 화면에서 새 이름 아래로 합쳐 보이지 않는다. 기록을 새 이름으로 옮길지는 따로 정한다
- Codex 구현은 실제 작업에서 아직 확인하지 않았다. 첫 구현 작업에서 커밋까지 되는지 확인한다
