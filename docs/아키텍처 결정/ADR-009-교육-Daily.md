# ADR-009: 교육 부서 시작과 Daily 자동 생성

- 상태: 확정 (2026-10-29 Zero 결정, 2026-10-30 문제·주간 보고·아침 학습 변경 추가)
- 관련: [ADR-007](ADR-007-회사-재정의.md), [ADR-008](ADR-008-팀장-팀원-구조.md), [회사 헌장 3장](../회사/01-헌장.md), [02-프로젝트 3.1](../회사/02-프로젝트.md)
- 볼트 쪽 기준: `zerohyeon-labs`의 `AGENTS.md`(에이전트 규칙), `Schedule/Daily 운영 방식.md`(사용자 설명서)

## 결정

1. 교육 부서를 시작한다. 담당은 교육팀장 **Eta (ENFJ, Claude)** 한 명이다. 이름은 그리스 문자 순서를 따른다 (다음은 Theta)
2. 교육 부서의 첫 일은 Zero가 볼트에서 정한 **Daily 운영 방식**(하루에 개념 1개)이다. 매일 아침 봇이 Daily와 개념 노트를 만든다
3. 일을 둘로 나눈다
   - 봇(결정론적): 가장 최근 Daily의 `오늘 할 것` 체크 읽기, 이어 하기(미완료)·새 개념(완료 또는 없음) 결정, 대기열에서 고르기, 선택 1개, 이번 달 완료 개수, Daily 파일, 대기열의 링크·`[x]` 표시, 볼트 커밋
   - Eta: 개념 노트 본문만 쓴다. 웹으로 사실을 확인하고 출처를 낸다. 파일은 쓰지 않는다
4. 일정은 매일 07:30(아침 보고 전)이다. 결과는 `#교육` 채널에 알리고, 채널이 없으면 `#대표실`에 알린다. `/daily`로 지금 만들 수도 있다
5. 매달 1일에는 지난달 사실(완료 개수, 월별 목표 완료 기준)을 함께 알린다. 다음 달 주제는 Zero가 정하고, 월별 목표의 월말 확인과 다음 달 대기열은 그 답을 받은 뒤에 채운다
6. 이전 Codex 자동화 2개(Daily Note 생성, 전날 피드백·Notion 투자 학습)는 없앤다 (`~/.zerosync/codex-automations-backup-20261029`에 보관)

### 2026-10-30 추가 (Zero 결정)

7. 개념 노트에서 `내 말로 한 줄 (선택)` 섹션을 뺀다
8. 볼트(Daily, 개념 노트)에는 학습 내용만 둔다. 문제는 모두 Discord `#교육`에서 A~D 버튼으로 푼다
   - 개념 노트의 `## 확인 문제` 섹션을 없앤다. Eta는 노트 본문과 따로 3문제(개념, 흐름, 실패·오류)를 JSON으로 내고, 봇이 DB에 두고 아침 알림 아래에 올린다
   - 이어 하는 날은 그 노트에서 아직 풀지 않은 문제만 다시 올린다
   - 복습 1문제: 3일·7일 이상 지난 노트 중 가장 최근 것의 문제에서 봇이 날짜로 돌려 가며 하나 골라 올린다 (이월하지 않는다, 에이전트 호출이 늘지 않는다)
9. 주간 학습 보고는 일요일 20:00에 `#교육`에 올린다 (`education.weekly`, `/weekly`)
   - 봇: 이번 주(월~일) 학습한 날 수, 끝낸 개념, 이어 하는 개념, 이번 달 대기열 진행, 이번 주 매일 문제(복습 포함) 점수, 지난주 주간 문제 점수
   - Eta: 다음 주를 위한 한마디 1~3줄과 주간 문제 5~8개 (주 1회 호출, 그 주 개념이 없으면 부르지 않는다)
10. 모든 문제(오늘 문제, 복습, 주간 문제)는 한 문제씩 A~D 버튼으로 올린다. 누르면 정답과 해설이 Zero에게만 보이고, 처음 고른 답만 DB에 남겨 주간 보고에 넣는다. 주간 문제는 주마다 한 번만 만든다
11. 개념 노트의 사실 확인 자료로 위키백과도 허용한다
12. 볼트에 생긴 Claude 데스크톱 예약 작업 `zerohyeon-daily`(06:00, 문제를 노트에 넣는 방식)는 일시정지한다. 생성은 봇의 Eta만 한다. 이 PR이 merge되어 봇이 교육 일정을 돌리기 전까지는 학습 자료가 자동으로 만들어지지 않는다
14. 아침에는 교육 파일(개념 노트, 대기열 표시)만 만들고 Daily 파일은 만들지 않는다. Daily는 하루를 정리하는 보고로 바꿔 비서 부서가 23:30에 만든다([ADR-010](ADR-010-비서-Daily.md))
   - 학습 기록(날짜, 오늘 개념, 이어 하기 여부, 완료 시각)은 DB `study_days`에 둔다. 다음 날 이어 할지 새 개념으로 갈지는 이 기록으로 정한다
   - 완료는 Zero가 `#교육` 아침 알림 아래의 "다 읽었다" 버튼으로 표시한다. 같은 개념을 이어 한 날도 함께 완료가 된다. 누르지 않으면 다음 날 이어 한다
   - 이번 달 완료 개수, 주간 보고, 월말 확인은 이 기록으로 센다. 볼트 커밋 메시지는 `docs(learning): 날짜 주제`다
15. 대시보드에 교육 화면(`/education`)을 둔다. 월별 목표(주제, 층, 자격증, 대기열 진행), 학습 대기열(구성 요소별 완료·진행 중·다음·대기), 최근 학습 기록을 보여 준다. 볼트와 DB는 읽기만 한다 (2026-11-01 Zero 요청)
13. 그림은 Codex 이미지 생성으로 넣는다 (2026-11-03 Zero 결정. 처음에는 넣지 않고 시험 뒤 정하기로 했다)
   - 시험: 봇과 같은 옵션(`codex exec --sandbox read-only --ephemeral --ignore-user-config --output-schema`)으로 이미지 생성 도구가 동작하고, 그림은 `~/.codex/generated_images/<실행>/`에 PNG로 생긴다. 한 장에 40초 안팎, 약 2만 토큰
   - 담당: 교육팀원 Iota(Codex 엔진, `concept_image` 단계, 읽기 전용)를 둔다. Eta는 그림이 도움 되는 날에만 그림 설명(`figure`: 그릴 요소와 화살표, 한글 이름표 2~10개, 한 문장 설명)을 내고, 없으면 그림 없이 낸다. 하루 최대 1장
   - 봇: 실행 전후 Codex 그림 폴더를 비교해 이번에 새로 생긴 PNG만 받는다(Iota가 알려 준 경로가 맞는지 확인). 가로 1024로 줄여(`sips`) 볼트 `Assets/YYYY-MM-DD - 주제.png`에 두고, 노트의 `## 흐름` 끝에 `![[…]]`와 `*그림: 한 문장*`을 넣어 노트와 함께 커밋한다. `#교육` 아침 안내에 그림을 붙인다
   - 그림 기준 (2026-11-03 Zero 결정. 처음의 "글자 없는 아이콘 그림"과 "비유 장면 컷"은 시험해 보니 이해가 어렵거나 유아적이었다)
     - 목적: 처음 배우는 사람이 그림과 이름표만 보고 흐름을 따라갈 수 있어야 한다
     - 그림체: 교과서·클라우드 구조도 같은 반실사 기술 그림. 요소는 실제 역할에 맞는 장비 모양(카메라, 산업용 컴퓨터, 서버 랙, 대시보드 모니터). 사람·캐릭터·만화체는 쓰지 않는다
     - 내용: 오늘 개념의 핵심 흐름 하나, 요소 3~8개. 왼쪽→오른쪽(또는 위→아래), 데이터는 실선, 설정·명령처럼 되돌아오는 것은 점선
     - 색: 흰 배경, 남색·회색·흰색에 청록 강조 하나, 가로 3:2
     - 이름표: Eta가 정한 한글 이름표(본문 용어 그대로, 각 10자 이내)만 글자 그대로 넣는다. 그 밖의 글자·숫자·로고는 넣지 않는다
   - 이름표 확인: 봇이 macOS 내장 글자 인식(Vision, `bot/education/ocr.swift`)으로 그림을 읽어 이름표가 모두 있는지 본다(공백과 가운뎃점 모양은 비교하지 않는다). 빠지거나 틀리면 그 이름표를 알려 한 번 다시 그리게 하고, 그래도 틀리면 그림 없이 낸다. 글자 인식을 돌리지 못하면 확인 없이 넣는다
   - Iota가 실패하거나, 다시 그려도 이름표가 틀리거나, 하루 한도(2회)를 넘으면 노트는 그림 없이 나가고, 안내에 "그림을 만들지 못했다"는 한 줄이 붙는다
   - 켜기: `projects.yaml`의 `education.illustrator: iota`. 없으면 그림 단계를 건너뛴다

## 맥락

볼트의 학습 운영은 Codex 자동화가 매일 Daily를 만들던 방식이었다. 항목이 많아 쌓이고 끊기는 문제가 있어, Zero가 2026-10-29에 "하루에 개념 1개" 방식으로 다시 정했다(볼트 `AGENTS.md`). 새 방식은 Mac에서 직접 요청해 만들다가 형식이 정해지면 자동화하기로 했고, Zero는 그 자동화를 ZeroSync 교육팀이 맡기로 했다.

## 선택지

1. 교육팀장이 볼트 규칙 전체를 읽고 Daily·노트·대기열을 직접 쓰고 커밋한다
2. 봇이 규칙 부분을 하고 교육팀장은 개념 노트 본문만 낸다 (채택)
3. Claude 데스크톱 예약 작업이나 Codex 자동화로 돌린다

## 근거

- 오늘 할 것을 정하는 규칙(체크 상태 → 이어 하기 또는 다음 항목)은 분명해서 코드와 단위 테스트로 고정할 수 있다. 에이전트가 하면 같은 규칙을 매일 다르게 해석할 수 있다
- 봇이 쓰는 주체가 되면 "외부에 쓰는 주체는 봇 하나"(AGENTS.md)와 맞는다. 커밋은 봇이 쓴 파일만 경로를 지정해 하므로 Zero가 볼트에서 고치던 파일이 섞이지 않는다
- 개념 노트 형식(섹션 순서)과 문제 형식(4지선다 3개, 보기 중복·머리표)은 봇이 검사하고, 틀리면 1회 다시 요청한다. 사실 여부는 판단하지 않는다
- 이어 하는 날은 에이전트를 부르지 않는다. 호출은 새 개념인 날에만 1회(형식 오류 재요청 포함 최대 2회)다
- 대기열·하루 한도·사용량 정지·실행 기록은 제품 일과 같은 구조를 쓴다. 대시보드 직원 화면에 Eta가 보인다
- 하루 개념 1개는 처음 이해하는 데 강하지만 잊지 않는 데는 약하다. 다시 읽기보다 문제로 떠올리기, 간격을 두고 다시 보기가 기억에 효과가 잘 확인된 방법이라 복습 1문제와 주간 문제를 더한다
- 문제를 Discord로 옮기면 정답이 노트 옆에 보이지 않고, 답과 점수를 봇이 기록할 수 있다. 노트는 읽을 거리로만 남는다
- 주간 보고의 숫자는 봇이 세고 Eta는 숫자를 고치지 않는다. 버튼은 `DynamicItem`(custom_id에 문제 번호와 답)이라 봇을 다시 시작해도 눌린다

## 회사 정보

- 볼트의 `회사/`는 git에서 빠진 비공개 폴더다. 개념 노트 단계에서 `Read(회사/**)`를 막고, 노트 본문에 `회사/`가 나오면 형식 오류로 돌려보낸다
- 선택 항목(플랫폼 지도 칸)은 대기열의 구성 요소 이름(`###` 제목)으로 봇이 만든다. 지도 내용은 읽지 않는다
- 회사·저장소·서비스 이름 같은 내부 정보가 들어가지 않았는지는 프롬프트로만 막는다. 봇이 내용을 판단하지 않으므로 Zero가 읽을 때 확인한다

## 트레이드오프와 남은 것

- 봇이 Mac에서 돌기 때문에 Mac이 꺼져 있으면 그날 학습 자료는 없다. 켜지면 놓친 일정을 한 번 따라잡는다. 빈 날은 채우지 않는다
- 월말 확인 뒤 월별 목표·대기열을 채우는 일과, `#교육`에서 Eta와 1대1로 대화하는 기능은 아직 없다. 다음 단계에서 정한다
- 문제는 DB에만 남고 볼트에는 쓰지 않는다. iPad Obsidian에서는 문제를 풀 수 없고 Discord에서 푼다. 볼트의 `AGENTS.md`, `Daily 운영 방식.md`, 개념 노트 템플릿도 이 기준으로 고쳤다 (2026-10-30)
- 완료는 문제를 다 풀었는지와 묶지 않는다. 완료 버튼만 본다
- 비서 부서가 시작되기 전까지는 Daily 파일이 없다. 학습 진행은 `#교육`과 주간 보고로 본다
- 봇을 처음 켤 때 지난 일요일 몫의 주간 보고를 한 번 따라잡는다. 그 주에 다룬 개념이 없으면 Eta를 부르지 않고 숫자만 올린다
- 그림 파일은 볼트 git과 iCloud에 쌓인다. 가로 1024 PNG 한 장이 300~550KB라 매일 그리면 1년에 110~200MB다 (그림이 없는 날은 0)
- 교육 부서의 업무 흐름·조직 문서(`docs/회사/03-업무-흐름.md`, `04-조직.md`)는 교육 부서 문서 작업이 develop에 들어온 뒤 맞춘다
