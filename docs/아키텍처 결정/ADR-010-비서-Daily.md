# ADR-010: 비서 부서 시작과 저녁 Daily·아침 보고

- 상태: 확정 (2026-11-01~02 Zero 결정)
- 관련: [ADR-007](ADR-007-회사-재정의.md), [ADR-009](ADR-009-교육-Daily.md), [회사 헌장 3장](../회사/01-헌장.md)
- 볼트 쪽 기준: `zerohyeon-labs`의 `AGENTS.md`("저녁: Daily"), `Schedule/Daily 운영 방식.md`, `Templates/Daily.md`

## 배경

ADR-009로 교육 부서가 아침에 학습 파일(개념 노트, 대기열)만 만들게 되면서 Daily 파일이 비었다. Zero는 Daily를 아침 할 일 목록이 아니라 하루를 정리한 보고로 받고 싶어 했다. 학습, 제품 부서의 일, Claude·Codex 토큰 사용량을 한곳에서 비교해 보고, 요약을 짧게 받는 것이다.

## 결정

1. 비서 부서를 시작한다. 담당은 비서팀장 **Theta (ESTJ, Claude sonnet)** 한 명이다
2. 매일 23:30에 그날의 Daily 파일(`Daily/YYYY-MM/YYYY-MM-DD.md`, 기존 위치 그대로)을 하루 정리 보고로 쓴다. 모양은 볼트의 `Templates/Daily.md`(2026-11-03 확정)를 따른다. iPad에서 위아래로 읽히게 표를 쓰지 않는다
   - 머리말: 이번 달 주제(월별 목표), 이번 달 완료·남은 개수(학습 대기열의 그 달 항목)
   - 오늘 학습: 개념 링크와 커리큘럼 ID(`교육 커리큘럼.md`의 `### SYS-01 주제` 제목), 완료 또는 내일 이어 하기, 오늘 문제 맞힌 수·안 푼 수, 복습 결과, 선택 항목과 했음·안 함. 선택 항목은 아침에 정한 것을 `study_days.optional`(스키마 v10)에 두고, Zero가 #교육의 '선택 했음' 버튼을 누르면 `optional_done_at`을 남긴다. v10 전 기록은 "기록 없음"
   - 오늘 한 일: 제품 부서의 작업 단계 변화와 PR 열림·merge만, 시각 순
   - 토큰: 봇·나(Zero) 사용량을 Claude·Codex로 나눠 한 줄씩, 이번 주 중 오늘의 비율, 구독 주간 한도 비율
   - 결정할 것: 승인 대기 작업과 열린 채용 제안. 없으면 비운다
   - 한 줄 요약 (Theta)
3. 일을 둘로 나눈다
   - 봇(결정론적): 사실과 숫자를 DB와 로컬 기록에서 센다. Daily 파일 쓰기, 볼트 커밋(Daily 파일만), Discord 게시
   - Theta: 그 사실을 읽고 한 줄 요약(한 문장)만 JSON으로 쓴다. 파일을 읽거나 쓰지 않는다. 요약을 받지 못해도 사실만으로 Daily를 쓴다
4. 보고는 `#비서` 채널에 한다(없으면 `#대표실`). 저녁 보고는 멘션하지 않는다
5. 아침 보고(08:00)도 비서가 `#비서`에 짧게 한다: 오늘 결정할 것을 먼저, 진행 중·어제 끝난 일은 건수만, 어제 Daily 경로. 결정할 것이 있을 때만 멘션한다. 주간 보고(월요일 08:00)는 `#대표실`에 그대로 둔다
6. 23:30을 놓치면(Mac이 잠들어 있으면) 다음에 켜질 때(보통 아침) 그날 것을 한 번 쓴다. 같은 날 저녁판 Daily가 이미 있으면 다시 쓰지 않는다. `/evening`으로 가장 최근 저녁 몫을 지금 만들 수 있다
   - 아침판 (2026-11-03 Zero 결정): 개념 노트는 Obsidian에서 읽는데 Discord는 `obsidian://` 링크를 누를 수 있게 만들지 않는다. 그래서 교육 아침 학습이 새 노트를 내면, 봇이 바로 그날 Daily의 아침판을 쓴다. 머리말과 `## 오늘 학습`(개념 노트 링크, 오늘 문제 수, 복습, 선택 항목)만 채우고 나머지 절은 "(저녁 23:30에 비서가 채운다)"로 둔다. 에이전트는 부르지 않고, `#비서`에 알리지 않는다. 볼트 커밋은 `docs(daily): 날짜 아침`
   - 저녁에는 아침판이나 Obsidian이 먼저 만든 빈 파일을 하루 정리로 다시 쓴다. Zero는 Daily에 직접 메모하지 않으므로 보존할 절은 두지 않는다
   - 볼트 GitHub 백업 (2026-11-03 Zero 결정): 저녁 Daily를 커밋한 직후 하루 한 번 볼트를 GitHub(비공개 `zerohyeon-labs`)에 push한다. 그날의 노트·그림·대기열·Daily가 한꺼번에 올라간다. force push는 하지 않고, GitHub에 이 맥에 없는 커밋이 있으면 올리지 않는다. 못 올리면 `#비서` 저녁 알림에 이유를 한 줄 붙이고 다음 저녁에 함께 올린다. 봇이 경로를 지정해 커밋한 것만 올라가고, `회사/`는 git에서 빠져 있어 올라가지 않는다. launchd에서 GitHub SSH 인증이 되는 것을 확인했다
   - Obsidian 핵심 플러그인 Daily notes의 저장 위치를 `Daily`, 형식을 `YYYY-MM/YYYY-MM-DD`, 템플릿 없음으로 맞췄다(볼트 `.obsidian/daily-notes.json`). "오늘의 Daily 열기" 한 번으로 오늘 Daily가 열리고, 거기서 개념 노트로 간다. `#교육` 아침 안내에도 Daily 경로를 붙인다
7. 토큰은 모든 범위를 센다. 봇이 부른 것과 Zero가 데스크톱 앱·터미널에서 쓴 것, ZeroSync 밖의 저장소에서 쓴 것까지 넣는다. 다른 저장소의 이름은 쓰지 않고 숫자만 쓴다
8. 볼트 원칙 "Daily는 두 절만"을 바꾼다. Daily는 위 2의 절로 이루어진 저녁 보고다 (`Templates/Daily.md`). 처음 구현(요약 1~3줄, 표)은 볼트 템플릿과 달라 2026-11-03에 템플릿 모양으로 맞췄다

## 토큰을 세는 방법

| 엔진 | 누가 | 읽는 곳 | 기준 |
|---|---|---|---|
| Claude | 봇 | `~/.claude/projects/**/*.jsonl` | `entrypoint`가 `sdk-cli`(`claude -p`) |
| Claude | Zero | 같은 곳 | 그 밖의 `entrypoint` (데스크톱 앱, 터미널) |
| Codex | 봇 | 봇 실행 로그(`agent_runs.log_path`) | `tokens used` 숫자. 봇은 `--ephemeral`이라 세션 파일이 없다 |
| Codex | Zero | `~/.codex/sessions/YYYY/MM/DD/*.jsonl` | `token_count` 이벤트의 세션 누적값 증가분 |

- 토큰 수는 입력(캐시 읽기·쓰기 포함)과 출력의 합이다. Claude 메시지는 같은 id가 여러 줄에 나오므로 한 번만 센다
- 기록 파일에서는 숫자와 시각만 꺼낸다. 대화 내용은 읽지 않고 어디에도 옮기지 않는다
- 이번 주 중 오늘: 월요일 0시부터 그날 끝까지 합계에서 그날이 차지하는 비율
- 구독 주간 한도: 그날 끝 전 마지막 값과, 그날 시작 전 마지막 값과의 차이(오늘 증가분). 둘 다 계정 전체(봇과 Zero) 기준이다
  - Codex: 세션 기록의 `rate_limits`(주간 창 10080분)
  - Claude: 로컬 기록에는 없다. 봇 Claude 실행기를 `--output-format stream-json`으로 돌려 실행 로그에 남는 `rate_limit_event` 줄의 `unifiedWindows.seven_day`(사용 비율, 초기화 시각)를 그 실행의 시각으로 읽는다. 23:30 Theta 호출에서도 값이 생기므로 그날 봇이 Claude를 안 불렀어도 하루 한 번은 있다. 공식 문서에 약속된 형식이 아니라 모양이 바뀌면 "기록 없음"이 된다 (2026-11-03 추가)
- `claude -p`를 봇 밖에서 직접 돌린 것(수동 스크립트)도 봇으로 센다

## 데이터

- `task_transitions` (스키마 v9): 작업 상태가 바뀔 때마다 `from_state`, `to_state`, 시각을 남긴다. 같은 상태 안에서 Zero가 입력한 것은 남기지 않는다
- `events.kind = pr_opened`: 봇이 draft PR을 연 때. merge는 기존 `merge` 이벤트를 쓴다
- `study_days.optional`, `optional_done_at` (스키마 v10): 그날 선택 항목과 '선택 했음' 버튼 시각
- 구독 주간 한도의 초기화 시각은 같은 창에서도 기록마다 1초쯤 흔들린다. 5분 넘게 다를 때만 창이 바뀐 것으로 본다
- 학습은 교육 부서의 `study_days`·`quizzes`·`quiz_answers`를 읽기만 한다

## 결과

- 아침에는 교육 파일만, 저녁에는 Daily 하나가 생긴다. Daily는 그날 하루의 사실을 한 파일에 모은 기록이 된다
- 숫자는 모두 봇이 세므로 Theta가 숫자를 지어낼 수 없다. Theta 호출은 하루 1번이다
- Claude 구독 한도 비율은 봇 실행 로그에서 읽는다. 놓친 저녁을 다음 날 아침에 쓸 때는 비서 호출이 그날 밖이라, 그날 봇 실행이 없었으면 Claude 한도는 "기록 없음"이다
- 이 결정 전(스키마 v9 전)의 단계 변화와 PR 열림은 기록이 없다
