# 2026-11-19

## 한 것

- 봇 제어 서버에 `POST /tasks`를 더했다 (ADR-014 추가 절). 웹 대시보드가 `{"project", "command", "title"}`를 보내면 Discord `/task`와 같은 `Engine.task_from_chat`으로 포럼 포스트를 열고 작업을 시작한다. 응답은 `{"task_id", "thread"}`, 웹에서 만들었다는 것을 운영 채널에 한 줄 남긴다.
- `task_from_chat`은 첫 단계(에이전트 실행)가 끝날 때까지 기다리므로, 웹 요청은 `background` 인자로 첫 단계를 봇의 백그라운드 작업에 넘기고 바로 응답한다. Discord 명령 쪽 동작은 그대로다.
- 실제 확인: 봇을 작업 브랜치 코드로 재시작한 뒤 curl로 jday에 "시험" 작업을 만들었다. 0.9초 만에 200과 작업 47이 돌아왔고, DB에서 PLANNING 상태와 기획 에이전트 실행을 확인했다. 토큰 없음은 401, 모르는 명령은 404였다.
- 지난 PR #51(직원 프로필 사진, ADR-015)은 develop에 merge되었다.
- 모든 Discord 글을 직원 이름으로 보내게 했다 (ADR-016). Zero가 보낸 화면에서 `#대표실`, `#비서` 글이 봇 계정 이름(ZeroSync)으로 보였다. 봇 계정이 직접 보내던 글을 그 채널의 웹훅으로 옮겼다.
  - `#대표실` 보고·채용 제안·홀딩 알림과 `#비서` 아침 보고·하루 정리는 비서실장, `#교육` 알림과 문제·완료 버튼은 교육팀장, 운영 채널은 `[별채]` 이름이다
  - 게시자가 이름과 사진으로 보이므로 `#비서`·`#교육` 글 첫 줄의 `[이름 · 직책]`은 뺐다
  - `#대표실`·운영 채널 웹훅은 처음 보낼 때 만든다. 얻지 못하면 그 글만 봇 계정으로 보내 알림이 사라지지 않게 했다
- Zero가 Developer Portal에서 봇 계정 이름과 아이콘을 별채로 바꿨다. 아이콘은 집을 안은 별 캐릭터이고, 원화(`output/characters/원화/00-별채/별채.png`)로 두고 `[별채]` 웹훅 사진(`assets/avatars/byeolchae.png`)도 같은 그림으로 만들었다.
- 운영 채널 이름을 `#별채-운영`으로 바꿨다 (Zero가 Discord에서 변경, 문서 반영). 봇은 채널 ID로 찾으므로 설정은 그대로다.

## 막힌 것·발견한 것

- 요청서 예시의 `"command": "task"`는 404가 난다. 값은 파이프라인 선언의 `command` 그대로(`/task feature`, `/task bug`, `/release`)다. 웹 쪽에 이 값을 써야 한다.
- 웹 요청도 Discord `/task`처럼 그 제품 채팅의 최근 대화를 작업에 옮겨 붙인다. 작업 47에는 jday 채팅의 확인용 대화가 붙었다.
- Discord 포스트와 운영 채널 알림 문구는 화면에서 직접 보지 않았다.
- 슬래시 명령의 답(Zero에게만 보이는 글)은 웹훅으로 보낼 수 없어 봇 계정 이름으로 나간다. 봇 계정 이름을 별채로 바꿔 해결했다.
- 웹훅 글의 버튼이 실제 서버에서 눌리는지는 아직 확인하지 않았다. discord.py는 봇이 가진 웹훅이면 버튼 글을 허용한다.
- 같은 날 두 PR이 같은 일지 파일을 만들어 merge 충돌이 났다. develop을 작업 브랜치에 합쳐 두 기록을 한 파일로 모았다.
